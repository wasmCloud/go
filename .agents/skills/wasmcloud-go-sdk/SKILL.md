# SDK changes

[`component-go.yaml`](../../../.github/workflows/component-go.yaml) is the source of truth.
If a command here differs from the workflow, follow the workflow.

## Layout

- Hand-written packages such as `keyvalue/`, `messaging/`, `nats/`, and `secrets/`
  wrap the generated bindings in an idiomatic Go API.
  Change behavior here.
- `imports/` and `exports/*/wit_exports/` are generated by `regenerate_bindings.sh`. Do not edit them.
  The `exports/*/export_*` trampoline packages next to `wit_exports/` are hand-written.
- The shared `wasi:*` bindings come from `go.bytecodealliance.org/wasi`,
  not from this repository.
- `component/wit/` holds the WIT for the SDK;
  `wit/deps/` is fetched, not authored.

## Checks

Run these in `component/` (or `plugin/`, adjusting the paths) and work through the list:

```
- [ ] gofmt -l .            (no output)
- [ ] GOOS=wasip1 GOARCH=wasm go build ./...
- [ ] GOOS=wasip1 GOARCH=wasm go vet $(go list ./... | grep -vE '/(imports|exports)/')
- [ ] go test ./...
- [ ] golangci-lint run ./...   (when installed)
```

If any step fails, fix the cause and re-run from that step.

- Unit tests run natively.
  The generated packages carry an `empty.s` so bodyless `//go:wasmimport` functions compile off wasm;
  test the hand-written wrappers, not the host calls.
- A bug fix needs a test in the package it changes that fails without the fix.

## Changing WIT or bindings

1. Edit the WIT in `component/wit/` (or `plugin/wit/`).
2. Install the `wit-bindgen` CLI version pinned as `SDK_WIT_BINDGEN` in
   [`airgap/versions.env`](../../../airgap/versions.env),
   from a tagged release, never `main`:
   `cargo install wit-bindgen-cli --version <SDK_WIT_BINDGEN> --locked`.
3. Run `./regenerate_bindings.sh` from the module directory.
   A new handler world must be added to `EXPORT_WORLDS` in the script.
4. Commit the regenerated bindings with the WIT change, in the same commit.

If the pinned `wit-bindgen` is not available, say so; do not hand-write or patch the generated code.

## Testing examples against your change

Examples pin the released SDK in `go.mod`,
so building one locally does not exercise your change.
Point it at the checkout the way CI does, without committing the result:

```shell
cd examples/components/<example>
go mod edit -replace go.wasmcloud.dev/component=../../../component
go mod tidy
wash build
git checkout go.mod go.sum
```

Do not commit a `replace` directive in an example or template.
Examples move to a new SDK version only through the release train and `airgap/bump-sdk.sh`;
see the toolchain skill.
